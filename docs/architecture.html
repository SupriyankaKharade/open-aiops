1. What Open-AIOps is

An open-source control plane for LLM traffic. Given a request, it should pick the best provider by cost, latency, and health, recover automatically when a provider fails or rate-limits, and report what happened: which provider served the request, how long it took, how many tokens it used, and what it cost.

Not in scope for the first version: a hosted service, a dashboard, a custom telemetry backend, storing prompts, and agent orchestration.

2.3 Principles

  1. The gateway knows about domain events, not observability vendors. It imports no OpenTelemetry or Prometheus code. Tracing and metrics subscribe independently to lifecycle events. Cost is gateway domain data and travels on those events.
  2. Telemetry never breaks a request. A failing subscriber or exporter is logged by error type and ignored. Subscribers must do bounded, local work. Exporting happens in the SDK's batching processors.
  3. Privacy by default. No prompts, completions, API keys, headers, or exception messages in any event, span, or metric. Enforced by a test that sends fake secrets through the pipeline.
  4. Cost is domain data, computed in the gateway where usage is known, and carried on events. It is an estimate: unknown models and missing usage produce a status, not an error.
  5. Open standards. OpenTelemetry (GenAI semantic conventions) for traces and metrics. Names live in one registry and are pinned to a version because those conventions are still in development.
  6. Local-first and free. Fakes for tests and demos, optional local models, in-memory exporters. No paid infrastructure.
  7. Bounded metric labels. Only provider, model, outcome, error_type. Request and tenant IDs appear on spans only.

2.4 Technology

Python 3.10 or newer (requires-python), pydantic v2 and pydantic-settings, httpx (async client, planned), opentelemetry-api and opentelemetry-sdk, pytest with pytest-cov. Everything is in-process and in-memory in V1: no database, no queue.

2.5 Deployment view

  • V1: a library plus examples/run_demo.py, run locally.
  • Later: an optional FastAPI service exposing an OpenAI-compatible endpoint, a Docker image, and a compose file with an optional observability container.

3. Low-Level Design (LLD)

3.1 Configuration (core/config.py, in review)

ProviderConfig (pydantic model)
  name: str                       non-empty, unique label (not the vendor)
  model: str                      non-empty
  cost_per_1k_input_tokens: float >= 0
  cost_per_1k_output_tokens: float >= 0
  expected_latency_ms: float      > 0

Settings (pydantic-settings BaseSettings)
  app_name: str = "open-aiops"
  debug: bool = False
  log_level: str = "INFO"         validated to DEBUG..CRITICAL
  default_timeout_ms: float = 30000   > 0
  providers: list[ProviderConfig]     parsed from a JSON string
  api_keys: dict[str, SecretStr]      keys by provider name
  env_prefix = "OPEN_AIOPS_"          (requested in review)
get_settings(): lru_cache singleton, no work at import time

Precedence: explicit arguments, then environment variables, then .env, then defaults. The priority field and plain-string api_keys in the current diff are being removed in review. Planned additions: unique provider names, an optional provider_type (vendor, for telemetry), and a nested section for observability settings.

3.2 Router (governance/router.py, built)

RouteRequest: input_tokens, max_output_tokens, max_latency_ms?, max_cost?

estimate_cost(p, req) = (req.input_tokens * p.cost_in_per_1k
                       + req.max_output_tokens * p.cost_out_per_1k) / 1000     # worst case

ModelRouter(providers)         raises ValueError if empty or duplicate names
  mark_overloaded(name) / mark_healthy(name) / is_overloaded(name)    KeyError if unknown
  route(req) -> ProviderConfig:
      eligible = providers not overloaded
                 and (no max_latency_ms or expected_latency_ms <= max_latency_ms)
                 and (no max_cost or estimate_cost <= max_cost)
      if none: raise NoProviderAvailable
      return min(eligible, key = (estimate_cost, expected_latency_ms))     # list order breaks ties

Synchronous, pure, no I/O. The overload set is process-local shared state, so per-request fallback must not use it.

Planned (INT-12): decide(req) -> RoutingDecision(ranked, rejected) where rejected maps provider name to overloaded, latency_budget, cost_budget, or circuit_open. route() keeps working and returns ranked[0]. ProviderConfig is imported from core.config.

3.3 Provider contract and adapter (INT-10, INT-11, planned)

ProviderRequest   messages, model, max_output_tokens, ...
Usage             input_tokens | None, output_tokens | None      None means "not reported"
ProviderResponse  text, usage, model, latency
Provider          async complete(request) -> ProviderResponse    (stream() later)

Errors (ProviderError base; each carries two flags)
  RateLimitError(retry_after_s?)   retryable, failover-eligible
  ProviderTimeout                  retryable, failover-eligible
  ProviderUnavailable (5xx)        retryable, failover-eligible
  AuthError, BadRequest            neither (the same request would fail elsewhere)

retryable decides whether the same provider is tried again (INT-14). failover_eligible decides whether the next provider is tried (INT-6). They are separate flags because they can differ later, for example a provider that is down for good should fail over without being retried.

OpenAI-compatible adapter mapping (one adapter reaches local models and many hosted APIs):

HTTP result Raises
429 (reads Retry-After) RateLimitError
timeout ProviderTimeout
401, 403 AuthError
400, 422 BadRequest
5xx ProviderUnavailable

Usage on the wire (prompt_tokens, completion_tokens) maps to the internal input/output names. The API key is read only when building the request header and never appears in logs or exceptions.

3.4 Resilience

Failover (INT-6): over a ranked list, try each provider with a per-attempt timeout and a total deadline.

for provider in ranked:
    try:   return await call(provider)            # within remaining deadline
    except failover_eligible error:  record it; continue     # immediate, no sleep
    except other error:              raise                   # bad request or auth
raise AllProvidersFailed(reasons by provider, error types only)

Known limitation: after a timeout the first provider may still complete and bill the request.

Retry (INT-14): retry the same provider N times before failing over. Exponential backoff with full jitter, honors Retry-After, capped by the request deadline. Clock, sleep, and randomness are injectable.

Circuit breaker (INT-15): per provider.

An open breaker excludes the provider from decide() with reason circuit_open. Every state change emits CircuitStateChanged.

3.5 Gateway orchestrator (INT-13, planned)

async complete(request) -> GatewayResult(response, served_by, attempts):
    request_id = new opaque UUID;  emit RequestStarted
    decision = router.decide(...);  emit RoutingDecided
    run failover/retry over decision.ranked, emitting for each attempt:
        AttemptStarted -> AttemptSucceeded | AttemptFailed | AttemptCancelled
        RetryScheduled / FallbackTriggered between attempts
    fill cost from usage (INT-31)
    emit RequestCompleted(total latency, total cost) or RequestFailed(error type)

The gateway never mutates the router's shared overload state per request, enforces the total deadline from default_timeout_ms, and imports no telemetry code.

3.6 Event contract (INT-28, planned)

Immutable events with: schema_version, request_id and attempt_id (opaque UUIDs), attempt_number (1-based, counts every attempt in a request), provider, model, timestamps, optional opaque tenant_id. Never: message content, completions, keys, headers, exception messages.

Started Valid terminal event (exactly one)
RequestStarted RequestCompleted or RequestFailed
AttemptStarted (non-streaming) AttemptSucceeded, AttemptFailed, or AttemptCancelled
AttemptStarted (streaming) StreamCompleted, StreamInterrupted, or AttemptCancelled (or AttemptFailed before the first chunk)

Markers between them: RoutingDecided, StreamFirstChunk, RetryScheduled, FallbackTriggered. CircuitStateChanged is provider-level.

EventDispatcher: ordered delivery, each subscriber wrapped so an exception is logged by type and swallowed, per-subscriber timing with a warning over a budget, immediate return when there are no subscribers. assert_well_formed(events) checks the state table in tests.

3.7 Pricing and cost (INT-18, INT-31, planned)

PricingRegistry.cost(provider, model, input_tokens, output_tokens) -> Cost using Decimal, prices per 1,000 tokens read from the same ProviderConfig list the router uses.

Status When
priced Known model, usage present
unknown_model No price entry
missing_usage The provider did not report tokens
free Explicit zero price (for example a local model)

Who does what:

Ticket Responsibility
INT-18 Pricing calculation: pure, no telemetry
INT-31 Gateway integration: compute attempt and request cost and attach it to lifecycle events
INT-29 Render cost on spans
INT-30 Render cost in metrics

Pricing never raises. The gateway puts the attempt cost on AttemptSucceeded and StreamCompleted, and the total on RequestCompleted. Cost is attributed only when the gateway has usage to price. A failed attempt normally reports no usage, so it carries no attributed cost. A timed-out call may still be billed by the provider, and the gateway cannot see that.

3.8 Observability subscribers (INT-29, INT-30, planned)

Span tree built from events (a registry keyed by request and attempt ID, cleaned on every terminal event so spans cannot leak):

request
 ├─ attempt 1  provider A   ERROR rate_limited   (event: retry)
 ├─ attempt 2  provider A   ERROR rate_limited   (event: fallback)
 └─ attempt 3  provider B   OK   tokens in/out, cost

Attributes come only from a single registry (semconv.py): gen_ai.provider.name, gen_ai.request.model, gen_ai.usage.input_tokens, gen_ai.usage.output_tokens, error.type, plus project attributes openaiops.cost.total, openaiops.cost.status.

Context note. Spans are built from lifecycle events, so an attempt span marks gateway lifecycle boundaries. It is not the active OpenTelemetry context while the provider call runs. Automatic child instrumentation inside provider calls (for example HTTP client instrumentation) will not attach to the attempt span unless an explicit context bridge is added later. That is out of scope for V1.

Metrics:

Instrument Type Labels
request duration histogram (seconds) provider, model, outcome
requests counter outcome
provider errors counter provider, model, error_type
retries, fallbacks counters provider
tokens histogram provider, model, token type
cost counter provider, model

4.3 Failure handling summary

Situation Result
Rate limit, timeout, or provider 5xx Retry (if configured), then next provider
Bad request or auth error Raised immediately, no failover
Every provider failed AllProvidersFailed with per-provider error types
No provider fits the budgets NoProviderAvailable
Deadline exceeded Raised with the attempts made so far
Subscriber or exporter failure Logged by type, the request is unaffected
Unknown model or missing usage Cost status recorded, the request is unaffected
Client cancels AttemptCancelled, then RequestFailed(cancelled), spans closed

4.4 Streaming (designed now, built later)

Failover is allowed only before the first chunk. After that an error ends the response as StreamInterrupted. Usage comes from the final chunk. The span stays open until the stream completes, is interrupted, or is cancelled.

5. Data Model Summary

ProviderConfig → RouteRequest → RoutingDecision → ProviderRequest → ProviderResponse(Usage) → Cost → GatewayResult(response, served_by, attempts), with lifecycle events emitted alongside. No persistence in V1: all state (overload flags, breaker state, latency averages, budgets) is in-memory per process. That keeps V1 free to run, and scaling out later means stateless workers with optional shared state.

6. Testing Strategy

  • Offline always: fake providers (scripted 200, 429, timeout, slow stream), fake clock and sleep, in-memory span and metric readers. No network, no API keys.
  • Layers: unit tests per module (one test file each), then integration tests through the gateway, then the golden scenario as both a test and the demo.
  • Hard invariants as tests: no secrets or prompt text in any exported telemetry; telemetry failure does not change the response; every started request and attempt reaches exactly one terminal event; spans never leak.
  • CI (planned, INT-9): pytest and ruff on supported Python versions for every pull request.

7. What Is Demoable

7.1 Today (no API keys, no network)

Only the router's decision logic runs. It is real but not yet visual.

Demo A: show routing decisions (works on main once PR #3 is merged).

python -m pytest tests/test_governance.py -v        # 9 routing tests

Or live, using the same providers as the test fixture:

from open_aiops.governance.router import ModelRouter, ProviderConfig, RouteRequest

def p(name, cost, ms):
    return ProviderConfig(name=name, model=f"{name}-model",
                          cost_per_1k_input_tokens=cost,
                          cost_per_1k_output_tokens=cost,
                          expected_latency_ms=ms)

router = ModelRouter([p("primary", 1.0, 800), p("secondary", 2.0, 300), p("local", 0.0, 2000)])
req = RouteRequest(input_tokens=1000, max_output_tokens=1000)

print(router.route(req).name)                                   # local: the cheapest
fast = req.model_copy(update={"max_latency_ms": 1000})
print(router.route(fast).name)                                  # primary: latency budget removes local
router.mark_overloaded("primary")
print(router.route(fast).name)                                  # secondary: the overloaded one is skipped

This matches the expected results asserted in tests/test_governance.py. After the follow-up that moves ProviderConfig into core.config, import it from open_aiops.core.config.

Demo B: configuration (after PR #6 merges). Set an environment variable and show typed loading and masked keys. Variable names will change to the OPEN_AIOPS_ prefix. After the review fixes, a key set in settings must not appear in repr(settings) or model_dump_json().
